# Land Management App

A simple, mobile-first web app for managing land listings: prices, areas, Google Maps locations, photos and videos (stored in your Google Drive), WhatsApp sharing and public pages for buyers.

**Stack:** Next.js (App Router) · TypeScript · Tailwind CSS · Neon PostgreSQL · Drizzle ORM · Google Maps · Google Drive · Vercel

## What it does

- **Dashboard:** live totals (all / available / sold) and recently added land.
- **All Properties:** cards with cover photo, price, area, place and status; search by title, property ID or village; filter by status.
- **Add / Edit:** every field from your brief. The property ID (`LND-00001`, …) is generated by a database sequence, so it is unique even if two are saved at once. Pick the location by searching, tapping the map, dragging the pin or using "my current location". Only the title is required.
- **Photos & videos:** uploaded straight from the phone/browser to Google Drive (one folder per property). Set a cover photo, add or remove files later.
- **Property details:** everything on one page, with Edit, Delete (with confirmation), Open Maps, Call, WhatsApp, Share and Copy link.
- **Sharing:** WhatsApp message (title, price, area, place, short description, public link), copy details, copy link, native phone share.
- **Public page** `/p/LND-00001`: only for properties you press **Publish page** on. It never shows internal notes.
- **Login:** one admin account. Every admin page, server action and API route checks the session on the server.

## Run locally

```bash
npm install
cp .env.example .env.local      # then fill it in (see below)
npm run db:migrate              # creates the tables in Neon
npm run dev                     # http://localhost:3000
```

Needs Node 20.9+.

### 1. Neon database

1. Create a free project at <https://neon.tech>.
2. Click **Connect**, copy the **pooled** connection string into `DATABASE_URL`.
3. Run `npm run db:migrate`. The migration in `drizzle/` creates the sequence, both tables, foreign key and indexes.

### 2. Admin login

```bash
npm run hash-password -- "your-strong-password"
openssl rand -base64 32          # use the output as AUTH_SECRET
```

Put your email in `ADMIN_EMAIL`, the hash in `ADMIN_PASSWORD_HASH`, and the random string in `AUTH_SECRET`.
In `.env.local` every `$` in the hash must be written as `\$` (the script prints that version for you). On Vercel paste the hash as it is.

### 3. Google Maps setup

1. Open <https://console.cloud.google.com>, create a project and **turn on billing** (Maps has a free monthly credit, but Google requires billing).
2. **APIs & Services → Library:** enable **Maps JavaScript API** and **Geocoding API**.
3. **Credentials → Create credentials → API key.**
4. Restrict the key: *Application restrictions → Websites*, add `http://localhost:3000/*` and `https://your-domain/*`. *API restrictions →* those two APIs.
5. Put it in `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`.

If the key is missing or wrong the form shows a clear message and you can still type latitude/longitude by hand.

### 4. Google Drive setup (photos and videos)

Files are stored in **your own Google Drive**, in a folder called `Land Management App` (created automatically), with a sub-folder per property. The app only sees files it created itself (`drive.file` scope).

1. In the same Google Cloud project, **enable "Google Drive API"**.
2. **OAuth consent screen:** choose *External*, fill in the app name and your email, add the scope `.../auth/drive.file`, add yourself as a test user, then **click "Publish app" (move to production)**. If you leave it in *Testing*, Google expires the token after 7 days and uploads will stop. `drive.file` is a non-sensitive scope, so no Google review is needed (you may see an "unverified app" warning once; that is expected for your own app).
3. **Credentials → Create credentials → OAuth client ID → Web application.** Add this authorised redirect URI: `https://developers.google.com/oauthplayground`. Copy the client ID and secret into `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
4. Open <https://developers.google.com/oauthplayground>, click the ⚙ gear, tick **Use your own OAuth credentials**, paste the client ID and secret.
5. In Step 1 type `https://www.googleapis.com/auth/drive.file` in the box, press **Authorize APIs**, sign in with the Google account whose Drive should hold the files.
6. In Step 2 press **Exchange authorization code for tokens** and copy the **Refresh token** into `GOOGLE_REFRESH_TOKEN`.
7. Start the app, go to **Settings → Test Google Drive**. It must say *Working*. Then try uploading one photo and one video.

Until all three Google values are set, the upload buttons are disabled and a setup message is shown. Nothing pretends to succeed.

How uploads work: the server asks Google for a one-time upload address, and your browser sends the file **directly to Google Drive**. That is why large videos work on Vercel (Vercel itself limits request bodies to 4.5 MB). Photos are shrunk to max 2000 px in the browser first. Files are not made public on Drive; the app streams them to visitors only for published properties (or to you when logged in).

## Deploy to Vercel

1. Push this folder to a GitHub repository.
2. On <https://vercel.com> choose **Add New → Project** and import the repo (framework: Next.js, no settings to change).
3. Add all variables from `.env.example` under **Settings → Environment Variables**. Set `NEXT_PUBLIC_APP_URL` to your final address (e.g. `https://land.yourdomain.com`). Because `NEXT_PUBLIC_*` values are baked in at build time, redeploy after changing them.
4. Run the database migration once from your computer with the Neon URL in `.env.local`: `npm run db:migrate`.
5. Deploy. Then add the Vercel address to the Maps key's website restrictions.
6. Sign in, open **Settings** and confirm Database, Maps and Drive all show as working.

## Project layout

```
drizzle/                 SQL migration (tables, sequence, indexes)
src/db/                  Drizzle schema + Neon connection
src/lib/                 auth, Drive client, formatting, validation, queries
src/app/(admin)/         dashboard, properties, settings (login required)
src/app/p/[code]/        public property page
src/app/api/media/       streams media from Drive (published or admin only)
src/app/api/drive/       starts direct-to-Drive uploads (admin only)
src/app/actions.ts       server actions: save, delete, publish, media
src/proxy.ts             redirects logged-out visitors (not a security boundary)
```

## Security notes

- Passwords are bcrypt-hashed; the session is a signed, HTTP-only cookie valid for 14 days.
- Server actions and API routes re-check the session themselves. `proxy.ts` is only a convenience redirect.
- Public queries filter on `is_published = true`; internal notes are never selected on public pages.
- Secrets live only in environment variables. Only `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is visible to browsers, as Google Maps requires; restrict it by website.
- Changing the admin password: generate a new hash, update `ADMIN_PASSWORD_HASH`, redeploy. Changing `AUTH_SECRET` signs everyone out.

## Known limits of version 1

- One admin user (by design, to keep it simple).
- Uploads happen one file at a time; a dropped mobile connection means retrying that file.
- Deleting a property deletes its Drive folder. Drive keeps it in trash for 30 days.
